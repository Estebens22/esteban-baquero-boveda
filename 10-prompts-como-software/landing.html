01La idea

Un prompt que solo devuelve texto libre es una corazonada: funciona hasta que no, y no sabes por qué. La vuelta: le exiges una salida tipada (un contrato de JSON) y la mides contra evals. El modelo propone; el esquema dispone.

entrada → [modelo] → salida JSON → [validar contra el esquema] → [medir con evals]

02Corre el ejemplo en 10 segundos

El kit trae promptkit.py — solo librería estándar — y un set de evals en data/:

cd kit
python3 promptkit.py --demo
python3 promptkit.py

Sin API key corre en modo MOCK (un clasificador por reglas que hace de stand-in del modelo). Con OPENAI_API_KEY usa el modelo real — y la salida pasa por el mismo validador.

03Las 3 piezas que importan

La salida tipada (el contrato)

Un esquema con enums y tipos. El validar() rechaza cualquier respuesta fuera de contrato con la razón exacta. Nada entra al resto del sistema sin pasar por ahí.

Los evals que la miden

Un set de casos con su salida esperada. Un caso pasa si la salida es válida y todos los campos coinciden. Metes los casos ambiguos y límite: ahí es donde el prompt se cae.

El ciclo de mejora

El reporte marca cada ✗ con el campo que falló. Ajustas el prompt, vuelves a correr y ves el accuracy subir. Eso es iterar con método, no a ojo.

04Llévatelo

Kit con promptkit.py, el set de evals y la guía. Cambia el esquema y los casos por los de tu tarea, y tienes un prompt que puedes mejorar como mejoras el código: con pruebas.
