01Qué vas a lograr

El camino completo: Dockerfile → contenedor → reverse-proxy con TLS → dominio → logs limitados → healthcheck. Al terminar, tu app está en vivo con HTTPS y dominio propio, y sabés exactamente qué parte es del servidor, del DNS y del contenedor.

02Deploy en un comando

El kit trae deploy.sh: build, run con restart automático y logs limitados, y healthcheck.

./deploy.sh mi-app 8080

La clave anti-403

nginx corre como usuario no-root; si los archivos vienen con permisos 600, da 403. Esto lo evita:

RUN chmod -R a+rX /usr/share/nginx/html
Límite de logs obligatorio: un contenedor que loguea sin tope llena el disco y tumba todo. Por eso corre con --log-opt max-size=10m --log-opt max-file=3.

03Dominio + TLS automático

Apuntá un registro A de tu dominio a la IP del servidor (DNS-only si usás Cloudflare, para el challenge). Luego, el bloque de Caddy:

tu-dominio.com, www.tu-dominio.com {
	encode gzip
	reverse_proxy 127.0.0.1:8080
}

El certificado Let's Encrypt se emite solo al primer hit. Verificá en vivo, no contra el pipeline:

curl -s -o /dev/null -w "%{http_code}\n" https://tu-dominio.com/
