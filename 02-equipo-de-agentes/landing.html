01La idea

Un orquestador reparte la tarea entre agentes con un rol claro, que comparten un state y se pasan el trabajo. Lo determinista va en código (herramientas); el criterio va en el modelo.

tarea → [Investiga] → [Analiza] → [Construye] → [Valida] → resultado
            usa tools            state compartido entre todos

02Corré el ejemplo en 10 segundos

El kit trae orchestrator.py — solo librería estándar de Python. Corre en modo MOCK sin API key:

cd kit
python3 orchestrator.py "Planea el lanzamiento de mi newsletter"

Para respuestas reales, poné tu OPENAI_API_KEY (funciona con cualquier API estilo OpenAI).

03Las 3 decisiones que importan

Roles con una responsabilidad

Un agente que hace todo = un prompt gigante y frágil. Dividí por verbo: investiga / analiza / construye / valida.

Estado compartido explícito

Los agentes se pasan un state (dict), no "se adivinan". Eso lo hace depurable.

Determinista vs criterio

Lo que se puede calcular va en código/tools; el juicio va en el modelo.

04Costo, latencia y errores

  • Menos pasos y modelo más chico donde alcance.
  • Cortá temprano: si Valida dice OK, no sigas.
  • Reintentos con límite y timeout en cada llamada (nada de loops infinitos).
  • Medí tokens por corrida y tiempo por agente.
